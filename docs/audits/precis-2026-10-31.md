# Précis course audit — 31 October 2026

**Verdict:** the current course is not a complete, faithful digital presentation of the owner's handbook. The most serious problems are altered source material, a broken path back to saved writing and model comparisons, and incorrect grammar advice for valid sentences. These are concrete reasons to rebuild the course around the original book rather than add another parallel guide.

## Scope and evidence

- Owner confirmed the source is **MASTER PRÉCIS WRITING STEP-BY-STEP HANDBOOK**, 22 numbered chapters plus appendices A–C.
- Audited source: `fadf344164210eaca9de9059eab11209d6bfa9ab`, confirmed as the live Hostinger fingerprint during this audit. An earlier probe returned `a9deffd6`; the only change to the Précis guide between those commits namespaces local working notes for preparation resets, without changing teaching content.
- Reviewed the importer, stored handbook, course scheduling, route entry point, composer/history, local checker, native endpoint and progress mutation code, and existing focused tests.
- Measured the stored catalogue: **25 chapter/appendix entries, 63 heading blocks, 193 body blocks and 108 app-generated reading units**. The six stored practice passages contain **43, 42, 40, 53, 81 and 45 words** respectively; all have no explicit question word limit. These counts describe the imported catalogue, not the unavailable original document.
- Ran existing focused tests: **18 passed, 0 failed**. Ran separate diagnostic probes that reproduce two incorrect grammar findings and the content-version tracking limitation below.
- The original DOCX/PDF was not found in the accessible workspace, Git history or connected Drive searches. Even the first handbook import commit (`a842d285`) contains the same worked-example placeholder. Full book-to-screen fidelity and the complete extent of omitted material remain unverified until the owner resends the original.
- This was a source audit, deterministic diagnostic run and read-only live fingerprint check. No authenticated production session, fresh PHP/MySQL integration environment or full browser accessibility audit was used in this audit. No production records or application code were changed.

## Findings, in repair order

### F1 — High: the import deliberately changes the book

**Evidence:** `scripts/precis/import-handbook.py:31–36` replaces chapter 2 and appendix C with editorial text. Lines 51–52 replace chapter 18, **Worked Examples: Beginner to Advanced**, with one instruction paragraph and filter answer-key material out of chapter 20. The course then renders those imported blocks under “original handbook” labels (`src/features/precis/Guide.tsx:300`, `:347`, `:434`).

**Impact:** preserving every *imported* block is not equivalent to preserving the owner's original book. Students cannot read the full worked-example chapter where the book places it. Some models survive separately on the server, but that does not restore the original chapter and commentary.

**Repair:** re-import the original book with an explicit preservation manifest. Keep author text intact; put clearly attributed editorial notes, including unverified examination-rule notices, alongside it. Keep teaching examples and solutions associated with their original sections. Do not describe transformed or omitted material as verbatim source.

### F2 — High: saved writing, genuine revisions and model comparison are disconnected from the course

**Evidence:** `src/pages/account/Precis.tsx:13` reads only the preparation-attempt query, then renders only `Guide` at line 54. It does not load a requested `writing`/`version`, show the returned writing-history list, or mount `History`. `Guide.tsx:493–501` opens `Composer` without its optional `detail` and discards the returned writing/version identifiers on save. `Composer.tsx:131` derives the existing writing record from `detail`; without it, a new save has no record ID and starts at version zero. `History.tsx:49` contains the model-reveal action, and line 223 requires at least two versions. The backend also requires two distinct saved drafts before revealing a model (`public/api/_precis.php:121–123`).

**Impact:** after a successful save the composer closes and clears its local draft, but the current page offers no way to reopen that saved record. Reopening practice starts a new record instead of revising the previous one. Old saved-writing deep links are ignored. The normal course UI cannot reach its own multi-version comparison/model workflow. This is an access/navigation failure, not evidence that the database has deleted students' writing.

**Repair:** retain the existing owned-writing API, immutable versions and history component. Restore one visible **My drafts and revisions** entry inside the same Précis workspace; honour saved-writing/version links; open the saved record after saving; pass its detail into the composer for revisions. Make worked-example reading and independent-practice comparison clearly distinct. No duplicate course is required.

### F3 — High: valid grammar is presented as an error to correct

**Reproduced using the actual local checker:**

| Valid sentence | Current finding | Problem |
| --- | --- | --- |
| “If it were possible, the school would offer evening classes.” | `it-plural`, certainty `detected`; suggests “it was” or another singular form | This is a valid irrealis/subjunctive construction, not a singular/plural disagreement. |
| “It is essential that he have access to the library.” | `he-have`, certainty `detected`; suggests changing “have” to “has” | The mandative subjunctive is valid in this construction. |

**Evidence:** `src/features/precis/writingAnalyzer.ts:70–82`. `WritingAnalyzer.tsx:78` describes detected findings as patterns to correct. Existing tests do not cover these cases.

**Impact:** students can be instructed to change correct formal English. General disclaimers about rule-based checking do not resolve a particular confident false correction.

**Repair:** keep reliable word counts, explicit limits and narrowly verified mechanical checks. Add regression coverage for these valid constructions. Make context-sensitive suggestions cautious or suppress them where the rule cannot distinguish valid usage. Do not present the checker as a complete grammar assessor or as the book's own marking method.

### F4 — Medium: an app-generated schedule replaces straightforward book navigation

**Evidence:** `guideModel.ts:29–62` groups source blocks in sets of at most three; `buildStudyDays` partitions those units by word weight. `Guide.tsx:284–370` requires choosing/creating a duration before the reading screen appears. Navigation is by scheduled day rather than an always-available full book table of contents. The “108 original handbook lesson sections” label describes app-generated groups, not 108 author-defined sections.

**Impact:** chapter explanations can be fragmented across screens and days. A student seeking the book's chapter or worked example has to navigate a schedule. Without selecting an attempt, the plan is memory-only and starts again after a refresh; this limitation is disclosed, but creates avoidable friction.

**Repair:** one book-first workspace with the actual table of contents, chapter/section links, worked examples and exercises in source order. Keep pacing as an optional view of that same content, rather than another course or a prerequisite to opening the book. Label generated reading units accurately.

### F5 — Medium: daily practice is selected by schedule position, not the book's exercise sequence

**Evidence:** `Guide.tsx:206` chooses a passage by `(dayNumber - 1) % passages.length`. `guideModel.ts:145–154` chooses a fixed check from the skill assigned to the final chapter of the day. The fixed checks are editorially adapted recognition drills (`public/api/_precis_questions.php:3`), not a transcription of the book's complete exercise/answer-key presentation.

**Diagnostic example:** in the default 14-day plan, the last day contains appendices B and C, maps the final source-note chapter to `central_idea`, and rotates to `example-2` on urban growth. That is schedule arithmetic, not a source-linked exercise selection.

**Impact:** exercises can recur independently of the method being taught, while actual answer-key content is missing from the reading chapter. The six short passages should not be mistaken for a comprehensive graded writing programme.

**Repair:** map each practice activity to the actual book section and skill. Preserve the book's exercise order and explanations. Keep clearly labelled supplementary checks only where useful. Verify the complete practice inventory against the original file before claiming completeness; do not invent extra passages or solutions to fill gaps.

### F6 — Medium: restoring the book needs a safe progress migration

**Evidence:** guide unit IDs use chapter ID and first-block position (`guideModel.ts:41–48`). Saved plans compare `handbook_sha` with the original DOCX hash (`public/api/_precis.php:86–88`); the importer records that raw-file hash even after replacing/filtering content (`import-handbook.py:53`).

**Diagnostic:** changing the text in the first catalogue slot leaves its unit ID at `1:0`; if the same raw book file is reprocessed by a changed importer, the raw source hash stays the same. Restoring omitted sections can also shift positional IDs.

**Impact:** a remake can misassociate old completed-reading IDs with changed text unless it explicitly migrates them. This is a confirmed design limitation and a migration risk, not evidence that current saved plans have already been corrupted.

**Repair:** retain the raw-book hash and add a hash/version of the served content manifest. Use source-anchored identities and an explicit migration or preserved legacy-progress view. Never silently erase attempts, writing, first responses or reading history during replacement.

### F7 — Medium: passing tests do not establish book fidelity or checker accuracy

**Evidence:** `tests/precisGuide.test.ts:15–54` checks preservation using a small synthetic chapter fixture, not a comparison with the owner's original DOCX. The current 18 focused tests all pass while both valid-sentence false corrections above are reproducible. The existing source hash identifies a raw input; it does not prove that every source paragraph reaches the course.

**Impact:** “tests passed” has been too easy to interpret as “the book is represented correctly”. The present tests establish useful software properties, not complete source fidelity or educational quality.

**Repair:** add original-document extraction comparisons, chapter/example/exercise manifests, saved-record reopen/revise/model browser journeys, and adversarial valid-English checker cases. Review the finished rebuilt flow against the book before publication.

## Acceptance criteria for the remake

1. One Précis workspace, one authoritative copy of the book, and one clear table of contents. No second overlapping course.
2. Every chapter, appendix, worked example, exercise and answer explanation accounted for against the resent original; editorial additions labelled separately.
3. Students can open a chapter directly, study a complete explanation, practise the corresponding method, save, reopen, revise the same record and compare versions.
4. Reading worked examples and independent practice have understandable, reachable workflows.
5. Valid subjunctive constructions above receive no confident incorrect correction. No semantic-fidelity, proficiency or official-score claims beyond verified capability.
6. Existing accounts, drafts, history, first responses and progress preserved or explicitly migrated.
7. Free access and no external AI/API dependency for the learning flow.
8. Source comparison, functional browser checks and owner review of the book-based version completed before replacing the live course.
