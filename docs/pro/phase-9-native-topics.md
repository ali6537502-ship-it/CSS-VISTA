## Existing architecture and delivery

The dashboard links to `/account/preparation?view=topics`. Students select an existing owned preparation attempt; the attempt’s Pro topic learning tab retains the topic, learning mode, section, search/category and history page in its URL. No separate account system, public lesson route, database service or raw-PDF viewer is introduced. Existing free Current Affairs/Vistagram readers and synchronized browser notes remain intact.

Lessons and fixed answer keys are stored in the native private MySQL database. No source files, Drive URLs, plaintext topic packages or correct answers are bundled into public assets or committed to this public Git repository. Authenticated/profile-complete accounts can view published catalogue metadata. Full content and new work require authoritative active Pro at the server. The initial lesson response omits every answer and explanation; server grading reveals only the result of the exact submitted check. Unauthenticated requests fail before content access, and responses use private/no-store policy.

Migration 022 adds topic metadata, immutable source editions, owned attempt progress, immutable submitted checks, scoped owner-admin request receipts and editorial events. Foreign keys preserve historical identities. Owner import saves a draft; it does not replace a published edition. Publishing checks the current owner MFA session, CSRF, edition ownership, validated content/hash, explicit review and optimistic publication revision. Withdrawal preserves students’ work and prevents further study. A corrected published edition starts separate progress while retaining earlier notes, writing and earned checks. Imports/publications have independent account-owned exact receipts, including recovery when a response is lost.

The private admin’s **Pro topic learning** workspace accepts prepared JSON packages, previews retained editions/sections/references/answer keys, records the review note and publishes the chosen version. Batch imports remain drafts and stop if a save cannot be confirmed. The owner-admin limit permits a complete 107-module import/publication cycle without requiring an unauthenticated publishing token. Direct HTTP access to internal topic helpers is denied.

## Recorded study and continuity

- Opening a lesson or bookmarking it gives no study credit. Starting and recording sections are explicit declarations.
- Understanding requires the studied sections and at least 80% in the fixed server check. Independent writing meeting the module’s stated minimum records practice, without claiming a mentor mark or AI assessment.
- Revision opens on the next scheduled Pakistan date, using different reviewed questions. Successful consecutive recall follows 3/7/14/30-day intervals; failure schedules tomorrow and restarts the interval sequence without erasing cumulative review history. Current due work is reported separately from mastery.
- Notes/writing use both progress and draft optimistic versions. Browser recovery keys include account, attempt and source edition. A changed device draft must be compared before explicitly adopting or replacing it; refresh does not quietly overwrite local work.
- Lost saves retain the exact request and consult the owned receipt first. Only confirmed absence permits exact retry or discard. Pro expiry removes full lesson access and blocks new premium work while preserving private saved notes, current writing per edition, earned check results and accepted receipts. These are source-edition histories; this increment does not claim an immutable archive of every intermediate note edit.

The six displayed learning states describe recorded work in a module. They are not official marks, a forecast of examination success, or a composite readiness score. Reading, fixed checking, word counts, revision and publication make no model requests. Commercial collection and provider activation remain closed by default; their earlier policy/credential/calibration dependencies are not resolved by this feature.
