## Owned reading and revision

The Reading & revision tab offers published articles, attempt bookmarks, explicitly marked-read sources and due revision. It links to the actual standalone reader with the selected attempt retained. The reader shows the same native attempt record and a return link. Publication area, date window, filter and page remain in the attempt URL across refresh; changing a filter resets its page. This is not another content store or a replacement reader.

Server metadata comes from published, active native briefing records or the existing packaged Vistagram index/posts. Future publication is excluded; missing attribution is not offered as a source-bound study record. Publication dates remain separate from server-recorded completion dates. Seven- and thirty-date publication windows use Pakistan Standard Time and never turn an older edition into this week’s news. References retain the publication’s labels/URLs/dates; publication and valid schema do not imply independent factual certification.

Additive migration 021 stores account/attempt-owned source identities, saved state, source snapshots/hashes, optimistic versions, first-read date, last review, next revision, cumulative recall count and the separate interval stage. It reuses the native preparation endpoint, account locks, shared exact-request receipts and immutable planner event history. Twenty articles are returned per page; personal snapshots are fetched only for the current page/source. No full article body or large MCQ dataset is duplicated in the attempt response.

Saving is distinct from reading. Opening a page, bookmarking or following an existing topic awards no read credit. An explicit reading declaration creates one distinct evidence link per source/attempt; a correction never inflates the count. Earlier evidence and the original first-read date remain saved. Read sources schedule their first recall for the next Pakistan date. Recall can be recorded only when due for the same read source version. Recalled independently advances the existing 1/3/7/14/30-day schedule; Needs review schedules tomorrow and resets the interval stage, while the cumulative recall history remains intact. These are self-reported outcomes, not quiz accuracy or mastery.

Changed sources require reading the updated version before recall. Unpublished/withdrawn sources keep their personal metadata snapshots in saved/read history but accept no new reading work. Up to three usable due-source candidates are drawn from the earliest twenty-five scheduled records into the reviewed daily plan. Unavailable or changed versions are skipped. Recording planner minutes remains separate from recording recall in the reader.

Existing Current Affairs evidence from Phase 8 deduplicates against reader declarations and retains its known original native completion date. An unknown earlier date is not inferred from a browser record. Vistagram reading, bookmarks, scheduled recall and cumulative reviews are shown separately in preparation evidence. Weekly/monthly reviews count original reading declarations by their completion date and immutable recall events by their actual server date; publication dates remain attached. None of this invents test results or a composite readiness percentage.

Account/attempt-specific pending mutations are preserved before sending. Response loss checks the owned receipt first. Only a confirmed absent receipt permits the exact retry or discard-and-refresh. Stale source/version conflicts never overwrite a newer device. Existing browser Vistagram keys, notes, collections, topic follows and account synchronization remain intact; earlier browser actions are not silently relabelled as current attempt work or merged with guessed dates.
