# Attempt planning and readiness — Phase 8

Implementation contract for the existing native account/preparation architecture. Draft development only; no production deployment or launch enablement. The existing browser planner and its saved data remain intact. The selected My CSS Attempt gains its owned planner through the existing My Preparation route.

## Versioned rules and evidence boundaries

`attempt-planner-v1` uses existing repository syllabus **sections** as study units, preserving their exact section/item mapping. It does not invent finer topic classifications from OCR line fragments. Optional interests remain the existing provisional shortlist; the religion-paper study choice is explicit. Essay independent practice is identified as a learning resource outside the syllabus-section coverage denominator. The existing official syllabus URL returned HTTP 503 on 2026-10-08; current official application rules/subject combinations are not certified by this planner.

Self-reported Learning/Covered states, recorded MCQ responses, source-derived past-paper reviews, linked human-written/evaluated answers, recorded tests and revision remain different evidence dimensions. Completing a study block defaults to Learning; marking a whole section Covered requires an explicit student declaration. A page view and task tick never assign marks, test accuracy, Exam Ready or mastery. No composite readiness score is produced. Missing assessments remain unavailable; recognition practice and model findings retain their existing eligibility/basis.

Daily durations are explicit estimates: coverage 30, revision 20, Grammar 20, Précis 25, writing 30, paper review 20, mentor follow-up 25 and dated Current Affairs 15 minutes. New work can use a shorter block down to 15 minutes when necessary; it does not promise that the whole source can be mastered in that block. At most 12 tasks are selected. Urgent work uses stable priority/key sorting. For routine work, one candidate from each available learning lane is considered before repeated coverage. Urgent candidates (priority 85 or higher) retain precedence; routine first-lane candidates rotate deterministically by Karachi date so a small daily budget does not permanently starve syllabus or writing. Due revision and evidenced difficulties precede fresh coverage. Declared revision stage favours studied work, not an invented calendar cutoff. Remaining target days affect a transparent capacity estimate, not a passing prediction.

Example: a 15-minute day gets one 15-minute block, not several unbudgeted tasks. With 60 minutes and due revision, Grammar review and uncovered syllabus, the rule considers a 20-minute revision, 20-minute Grammar block and a 20-minute coverage block. Missing Current Affairs or a paid-only resource is not replaced with dummy content. A reduced budget never deletes recorded completion; existing actual/partial work is shown and no additional work is allocated beyond the available budget.

Plans are previewed and explicitly saved. Stable source keys and owned receipts prevent duplicate tasks. A changed attempt, source/evidence, plan version or proposal requires a fresh preview. Replanning changes outstanding allocations while preserving completed/partial tasks and immutable action history. Older pending work is shown as overdue, not accumulated automatically into every new day. Explicit moves preserve their original identity/history and check the destination budget. Completion, partial work, skipping, deferral/replanning and rescheduling are distinct.

Revision uses configurable teaching intervals 1, 3, 7, 14 and 30 days after reported study/review, with a needs-review outcome returning to one day. These are study defaults, not calibrated exam mastery. Grammar keeps its existing question revision schedule and maintenance after Day 30. Existing Précis recognition and source-bound feedback remain distinct.

Weekly (7-day) and monthly (30-day) checkpoints compare adjacent equal Karachi-date windows and report actual recorded work. Imports/earlier coverage declarations are not labelled newly learned material. New drafts and rewrites are counted separately; mentor percentages use summed obtained/maximum marks with first answers and repeat answers separate. Linking an old record retains its original event date. No missing activity is supplied with invented figures or narratives.

## Persistence, UI and release

Additive native tables hold attempt settings, unit progress, daily plans, task allocations, explicit evidence links and immutable planner events. Account locks, ownership/profile/CSRF checks, optimistic versions and shared request receipts protect saves. Normal planning, readiness, reports, imports and revision make zero AI calls. Existing identities, entitlements, evaluation records, browser keys, free planner and MPT logic are not reset.

The attempt view leads with Continue Learning and Today's Plan, then Revision Due. Coverage, readiness, history/reviews and settings are secondary views. The same attempt is retained in course/feedback links. Mobile stacks tasks, explanations and actions in that order; desktop uses a readable main list, budget cards and evidence grids. White surfaces, slate/indigo emphasis, existing Tailwind controls/icons and visible labelled statuses match the current learning workspaces.

Supported recovery persists an exact pending mutation in account/attempt-specific sessionStorage before sending. Response-loss reads the owned receipt first. A confirmed absent receipt allows retry of the same request or discarding the unaccepted recovery copy; an accepted mutation restores authoritative state. No automatic overwrite after a conflicting version. Server history works across signed-in devices and after subscription expiry.

Validation must cover rule examples/budgets, stable identity, differentiated evidence, canonical hashes/migration parity, ownership/CSRF/profile, stale proposals, concurrent writes, replay, completion preservation, moves/replanning, revision intervals, imports, original evidence dates, result-release safeguards, expiry and zero AI usage, plus complete browser flows and mobile layouts.

Sections are existing source-map units with variable size, not independently verified atomic topics. Earlier imported study dates remain unknown.
