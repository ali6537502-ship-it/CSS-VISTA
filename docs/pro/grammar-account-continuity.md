# Grammar account continuity and evidence profile

8 October 2026. Additive Phase 4 increment on the existing draft branch. Native React/TypeScript → same-origin PHP/PDO → existing MySQL account and preparation-attempt ownership. No production migration or deployment. Public Grammar remains free; current full-profile requirements apply to account synchronization, without gating public lessons or browser practice. Active Pro is unnecessary for ordinary practice, saved Grammar history or this deterministic profile.

## Student journey and design

My Preparation → selected attempt → Continue Grammar / Grammar Profile. A labelled attempt selector also appears in the course. “This browser only” preserves the established isolated account key; guests retain v3 fallback and their own v4 key. An explicitly selected attempt is remembered in its own account namespace for later course visits; choosing browser-only clears that preference. No attempt is guessed from target year and no guest progress is silently adopted by an account. Explicit attempt selection creates a separate namespace. An empty attempt offers **Copy earlier browser progress into this attempt**, retaining the original browser record and marking the imported account evidence as self-reported.

Guided lesson → authored practice → saved position/drafts → Error Lab/revision → profile → next lesson. The selected attempt is retained through Lab, contextual lesson and reference links. Expression findings link to their writing's owned attempt, preserving exact writing/version return. Day 30 completion keeps every lesson accessible; the profile becomes a maintenance summary with due reviews, distinct first-response evidence, writing findings and links back to practice.

Local design contract: existing Grammar/Expression graphite hero, white study surfaces, restrained indigo controls, slate body text, rounded 12–24px panels, 44px actions, visible keyboard focus and real progress. Mobile panels and controls wrap; no animation is necessary to interpret evidence. Profile defaults to active lessons, with Needs attention and All lessons filters; its interpretation details are expandable. No simulated activity, fabricated students, readiness prediction or mastery score.

## Storage and recovery

`server/sql/015_grammar_progress.sql` and the parity-tested `_grammar_schema.php` add `grammar_progress` keyed by an owned preparation attempt, with restrictive native foreign keys. Current v4 course state is preserved: completion/best scores, notes, sessions, draft writing, first drill responses, drill history, Lab/correction drafts, Lab history and revision schedules. Existing completed Lab and drill results are preserved when a snapshot omits them; current round first responses cannot be rewritten by retries. History remains bounded at the established 50 Lab / 100 drill records.

`GET /api/student/grammar.php?attempt_id=UUID` returns owned state/version, import provenance and a deterministic profile. `POST` accepts only request_id, attempt_id, expected_version, state and optional import_browser. Native authentication, current account header, full profile, CSRF, write rate limit and owner row lock are used. A canonical payload hash plus the existing learning_requests ledger gives exact retry identity and small receipts. Compare-and-swap rejects stale devices with 409. The authored catalog validates question IDs, answer option ranges, correction IDs and all state fields. Server-only catalog/schema/helpers are denied direct HTTP access by the Hostinger configuration. The catalog is generated from actual authored data and checked in CI.

Account/attempt browser state uses `cssvista:grammar-course:v4:account:USER:attempt:ATTEMPT`; the v1 sync envelope separately records the base version, dirty flag and exact pending snapshot/request ID. Debounced 2.5-second saves are serialized. Edits made while a request runs remain dirty and follow after its receipt. A response lost after the server commit replays its exact identity before accepting the next version. Leaving a page retains unsent work in that browser for recovery on return; save status never claims pending work is available on another device. Account changes ignore obsolete responses.

A conflict keeps the browser draft and offers export plus explicit **Keep browser backup and load account copy**. Reload creates a new owned backup key before replacement. There is no silent merge, force save, remote reset or deletion endpoint. Storage failures are visible and pause automatic saves; API failures preserve drafts and expose retry. Existing notes longer than 20,000 characters remain unchanged. Oversized server submissions fail explicitly (4MiB overall, up to 1,000,000 characters per legacy note); the browser record/export remains available rather than being silently truncated.

## Profile interpretation

`grammar-self-practice-v1` uses first-seen daily-drill and Error Lab responses to **distinct authored question IDs**, graded against preserved answers on the server. An additive question evidence map survives course restarts, histories falling out of the display window and same-question retries. Best practice scores, imported completion, opening a lesson, model reveals and checklists never become positive accuracy evidence. Imported answers remain labelled self-reported practice, not verified examination results. Warm-up latest-answer maps do not substitute for first-response evidence.

Each real course lesson has its own row; the mixed lesson on Day 29 is not misrepresented as precise subskill evidence. States:

- Not started: no session/completion or first-response evidence.
- Learning: session/completion exists, without first-response evidence.
- Practising: distinct first responses exist, below the following review/trend criteria.
- Needs review: unresolved first-response/notebook/revision error or recurring Weak writing finding. An earlier question error resolves only after two spaced successes, even if its notebook entry was cleared.
- Improving: at least eight distinct responses, at least 70% supported by a correct first response or two spaced successes, at least three questions with two spaced successes, no unresolved questions and no recurring Weak writing finding. The displayed first-response accuracy is never rewritten.

Review timing continues to use the existing browser clock and schedule; it is a self-study trend, not a certified assessment. Server calculation time determines current due counts. Stable and Mastered are withheld until calibrated independent assessment opportunities and an evidence policy are available. No thresholds imply examination marks or guaranteed readiness.

Independent sentence/paragraph/confirmed-handwriting findings use the existing normalized Expression skill codes and audited lesson mappings. Queries enforce both account and **selected attempt**, successful feedback only, a 30-day window, at most 200 operations/100 different wordings and deduplication by text hash. Three different writing records are necessary for Weak; omitted findings are merely a writing feedback trend. Findings are displayed separately alongside practice and can override a positive practice trend. Absent/unreviewed writing never counts as correct. Profile loading/calculation performs no provider calls and consumes no AI allowance.
