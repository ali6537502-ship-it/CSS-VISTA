## Additive 028 — Factbook restore receipts

`028_factbook_backup_receipts.sql` matches the named-lock runtime initializer (`tests/workspace/factbook-backup-unit.php` checks exact SQL parity). It adds only an account/request key, canonical payload hash, confirmed count/result metadata and server receipt time. It stores no backup bodies, image bytes, learning progress or provider operations. Both original 026 files and 027 remain unchanged. Include the full filename/checksum in the eventual host inventory; neither a local initializer nor a local MariaDB rehearsal proves the host has applied it.

Factbook v2 exports all twelve existing owned tables, including archive/trash states, blocks, collections, preferences, saved versions and embedded private raster bytes. JSON body columns travel as stored JSON strings, preserving empty objects/arrays and original text. The native restore validates the graph and images before staging, allocates new owned IDs, retains originals and writes the full copied graph plus receipt in one SQL transaction. New copies preserve original timestamps; imported history labels source dates as unverified. Merge appends entries/members while reusing matching folders without replacing their settings. Preferences require explicit selection. Legacy v1 nested files remain supported when their image bytes are complete; missing bytes/relations fail rather than silently skip.

Limits are 16 MB JSON, 10,000 total records, 8 MB aggregate image bytes, 5 MB/16 MP per raster and the existing 500 MB private image quota. Oversized exports/restores fail explicitly; a larger streaming/operator workflow remains unfinished. Downloads use compact JSON so formatting does not push an accepted file past the byte limit.

Generated private image files are staged with exclusive creation, restrictive permissions, flush/fsync and metadata-only manifests. Ordinary failed transactions roll back and remove staged bytes. A worker killed before commit leaves request-labelled files for cleanup on the next non-replayed restore under the same account lock. If commit acknowledgement is uncertain, keep the bytes and query the account receipt first. Cleanup never removes referenced files or sweeps legacy uploads. Tests terminate a worker before commit and after a real commit before acknowledgement; they do not simulate actual PDO commit-ack transport failure, host power loss, directory fsync or every host filesystem condition. A fresh host database/private-storage restore remains a release gate.

Retain 028 and its historical receipts during presentation rollback; disable new restore writes rather than dropping confirmed records or replaying backup files. Collection edits and ordinary later changes retain historical receipts; an explicit full Factbook wipe clears that account's receipts. Images remain outside the public tree. Never recover another account's retained pointer or file without explicit account-scoped review.
