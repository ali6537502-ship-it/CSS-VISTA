# Phase 5B — source-bound Précis feedback and revision evidence

Implemented on the existing foundations branch, draft PR #78. This adds the permitted personal evaluation journey to Phase 5A; **live AI remains disabled**. No production migration, merge, release, payment collection or real provider invocation occurs.

## Input and teaching boundary

The server accepts an owned immutable **Précis Lab version**, never browser-supplied replacement text, source or title. An ordinary generic `kind=precis` version without the Lab's source/title context cannot be evaluated. The operation freezes the original, attribution, explicit length instruction, saved student text, title, optional central-idea note and versioned twelve-criterion rubric. It sends only relevant normalized writing-finding codes from the same account/attempt as background; self-ratings, other students' writing, scratch notebooks, model answers and examination marks are excluded.

The dedicated prompt compares central idea, argument structure, selection, compression, paraphrasing, fidelity, qualifications, coherence, grammar, economy, title and independence **against the original**. It diagnoses a supplied controlling-idea note as accurate, too broad, too narrow, incomplete or distorted; absent/uncertain notes remain explicit. It supplies targeted hints and explanations, not an ideal central idea, replacement title, complete model answer or full essay/subjective-answer marking. Source claims are not endorsed or independently fact-checked by this evaluation. Existing delayed handbook comparison remains separate.

Technical bounds are an original ≤2,000 words and one connected draft ≤700 words / 6,000 characters. They are hosting/payload limits, not official examination rules. The original practice's explicit limit remains visible; exceeding it is a revision issue, not a reason to delete the draft. Without an explicit limit, ratios are guidance. No automatic exam mark or shortening-as-improvement claim is introduced.

Strict output validation requires all twelve distinct criteria, permitted statuses, bounded text and exact source/student evidence. Positive `supported` evidence must quote both source and student wording; title evidence must quote the actual saved title. Missing ideas can have an empty student excerpt, with actual source evidence. `not_assessed` carries no evidence claim. The optional note diagnosis quotes the actual note and source. Shared language findings reuse canonical codes and exact draft anchors. Malformed, extra-field, invented-anchor and partial-rubric output fails before educational settlement. These guards validate structure and quotation, **not semantic marking accuracy**; provider calibration is still required before launch.

## Lifecycle, privacy and accounting

Native authentication, complete profile, CSRF, expected-user identity, ownership and bounded account/network write rates remain authoritative. New feedback requires active Pro, a nonzero configurable Précis allowance, private approved/model-verified provider configuration, CURL, a reviewed processing notice/version and `CSSV_PRECIS_ENABLED=1`. The feature defaults off with empty disclosure fields. Configuration readiness is not proof that production provider capability or educational accuracy has been verified.

The existing atomic ledger enforces **two successful evaluations per Asia/Karachi day** by default, with used plus reserved accounting and a separate accepted-request cap of three times the allowance. A request's identity binds feature/version/text hash and acknowledged processing policy. Exact replay returns its existing operation, including after expiry. An account lock rejects competing identities for the same completed/reserved/in-flight/unknown version. Useful feedback, canonical writing findings and successful allowance settle in one transaction. Provider dispatch runs after locks end, once, without automatic retries or fallback. Known failures release successful-use reservation while retaining accepted requests and reported usage; ambiguous outcomes remain reserved. The common operation sweep releases undispatched work and marks stale dispatched work unknown without resending it.

Additive migration **017** stores operation-bound input snapshots and a canonical decoded-value hash. This survives MySQL JSON key/whitespace normalization. Prompt/rubric version, source hash and immutable student-version hash are checked. Invalid snapshot preflight releases without a dispatch count. Accepted work can finish after expiry and keeps its reservation's original Karachi date. Later source edits cannot substitute another original or rubric into an accepted operation.

The browser records only a scoped request receipt (account/version/UUID/policy), before sending. A lost response/reload exposes **Recover saved feedback request**: read the owned receipt first, replay only a missing/undispatched accepted identity, and never issue another request for in-flight/unknown work. Terminal results remain server-owned history. Browser storage failure is reported with an in-memory recovery path; the actual saved writing remains intact. Account-keyed mounts, expected-user checks and abortable reads isolate account changes. Status reads and bounded pending polling do not invoke models.

## Revision and linked evidence

Every saved diagnosis remains attached to its exact source, title and text version. Attempt 2 is written independently in the existing Composer; Attempt 1 and its feedback remain readable. Comparison displays actual criterion-status changes and language findings **No longer reported / Still reported / Newly reported**, alongside the already deterministic length/title/wording comparison. Both versions must have successful feedback before assessed changes appear. No comparison, profile, drill, lesson or history visit makes a model call. Changes in reported status are prompts for review, not proof that every issue has been resolved.

Canonical language findings feed the existing Writing Error Profile and attempt-specific Grammar Profile. Links use the actual server-authored lesson mapping and carry writing/version/attempt through course, reference and Error Lab return paths. Existing Grammar datasets, saved position and free access are preserved.

The separate Précis writing-evidence panel uses the newest 200 successful operation rows from a 30-day window, retaining at most 100 distinct original-source hashes. Revisions and repeated copies of one original do not become independent sources. Three sources reporting difficulty establish `Weak`; explicit supported evidence on the latest three assessed originals, with previously recurring difficulties, supports `Improving`. Absence/unassessed criteria cannot establish improvement. `Stable` and `Mastered` remain withheld until semantic calibration; fixed recognition evidence stays distinct. Aging changes the rolling profile without deleting saved feedback or history.

## Validation and launch limits

Validation covers pure rubric/quotation/schema rules, canonical snapshot hashes, native API/database authentication and ownership, strict payload/size/shape limits, immutable context, concurrent allowances/identities, exact receipt recovery, malformed output, unknown/no-retry, disabled/corrupt preflight, Karachi midnight/expiry, independent-source evidence, shared Grammar findings and expiry-safe history. Browser verification uses conspicuously labelled synthetic output in the disposable database; it does not assert real model accuracy.

Production launch still requires verified provider account/model capability, calibrated source-fidelity/title/central-idea assessment on reviewed examples (including prompt-injection cases and ambiguous originals), approved disclosure and retention, production operation recovery/cron validation and explicit release authorization. A strict schema cannot guarantee that a model's explanations or hints are pedagogically correct or never reveal too much. No actual provider price, retention promise, exam correctness or certified mastery is claimed here.
