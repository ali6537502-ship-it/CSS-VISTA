# Provider activation and academic validation

The existing server-side Responses transport is retained. New studios use it through the existing account/operation/reservation ledger; no browser key, second provider client, independent counter or invented model-access claim is introduced. The configured model must actually be available to the production account. A configuration flag is an operator assertion, not proof of successful provider access.

The endpoint contract is the official Responses API (`https://developers.openai.com/api/reference/resources/responses/methods/create`). Structured output, text input, output-token bounds and `store:false` are necessary technical controls. They do not establish academic accuracy, zero retention, acceptable pricing, vision access or account-specific model availability.

## Required release evidence

1. Inspect the native production administrator's private configuration using the established authorized connection. Record readiness booleans and the selected non-secret model identifier; never record keys. This workspace currently has no provider secret binding, native hosting/database identity or production administrator session.
2. Verify that account's actual model access and supported text/image capabilities against current official documentation and an approved bounded request. Preserve the response identifier, reported model, schema-validation outcome and relevant token accounting in a private validation artifact. Do not re-dispatch an ambiguous request.
3. Review the processing notices and provider retention/handling terms. Keep each feature closed until its notice/version and feature authorization are valid. Handwriting additionally requires the approved image retention, limits, cleanup execution and readable-image confirmation policy.
4. Test reviewed examples through each actual feature's purpose-built prompt and validator. Evaluate academic usefulness separately from JSON validity. The common writing validator must not replace the Précis, handwriting, tutoring or reasoning-specific validator.
5. Approve feature-specific limits. Sentence Studio shares the existing sentence bucket. Argumentation, analysis and essay feedback have separate configurable buckets defaulting to zero; an owner policy question is pending. Précis and all older allowance defaults remain intact.
6. Confirm a real native student workflow and its saved operation/feedback, version comparison and expiry history with an authorized test account. Isolated synthetic fixtures are explicitly excluded from this evidence.

## Reviewed-example coverage required

- Sentence/paragraph: a correct sentence, agreement error, dangling modifier, ambiguous pronoun, qualified claim, deliberately unconventional but grammatical wording, and a prompt injection embedded as student text. Check meaning preservation and specific hints; do not replace the student's work.
- Argumentation: relevant supported reasoning, a weak inference, circular reasoning, a serious counterargument, qualified rebuttal and an explicitly unverified statistic. Check every documented qualitative criterion and reject invented factual verification or official marks.
- Analysis: description alone, a plausible mechanism, a competing cause, correlation mistaken for causation, an unsupported assumption, trade-offs and a counterfactual. Check that feedback identifies a real inferential gap and gives one next question.
- Essay: a theme-bound thesis, off-theme thesis, overlapping outline, balanced outline, unsupported factual support and an independent draft. The real 25-theme roadmap remains a research source, not a bank of verified statistics.
- Précis: faithful unconventional wording, missing central idea, omitted essential detail, unsupported addition, distortion, poor compression, title mismatch and revised attempts. Use the actual original passage and approved handbook; shorter is not automatically better.
- Handwriting: clear and unclear genuine handwriting, unreadable input and ambiguous words; confirm the extracted wording before any diagnosis. Use approved non-private samples, not production student images or printed-text fixtures represented as genuine handwriting.
- Ask VISTA: an in-source concept, an understanding check, a request for unsupported contemporary facts, fabricated-citation pressure and source prompt injection. Ensure citations quote the exact saved bounded source and uncertainty remains explicit.

The existing native tests and new `tests/skills/ai-security.mjs` exercise lifecycle/validation using labelled **TEST ONLY** transports. They prove no academic or real-provider capability. Real-provider validation remains blocked until the legitimate private connection and approved operating policy are available. No affected production AI flag is activated by this release.
