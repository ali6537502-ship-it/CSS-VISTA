# Phase 5A — handbook course and independent Précis practice

Implemented in draft PR #78. Not merged, deployed or commercially launched. This is the first complete Précis increment; source-bound personal evaluation is the next increment, not an implemented capability here.

## Source and pedagogy

The actual owner-supplied `Master_Precis_Writing_Handbook(1).docx` is the primary source. `scripts/precis/import-handbook.py <docx>` imports native paragraph, heading, bullet and table blocks; the generated private PHP catalogue records its SHA-256. All 22 chapters and appendices A–C are mapped into the account course. Five chapter-18 worked passages and chapter-20 Drill D become six practice sources. Full models are excluded from the ordinary catalogue and lesson blocks; chapter 18 directs students into practice, and chapter 20's answer key is handled through drills / the delayed comparison path.

The optional 30-day sequence follows chapter 21: Days 1–5 central idea, 6–10 selection, 11–15 compression, 16–20 connected drafts, 21–25 mixed arguments, 26–28 timed work, 29–30 error review. The supplied worked passages are **short instructional examples**, not authenticated past questions, fresh daily papers or full exam-length simulations. The handbook's suggested volume of five short passages per day and 100–180-word paragraph work remains a practice recommendation; this increment does not claim a bank of 150 fresh passages. Students may add an attributed private passage and its actual explicit word limit.

The writing flow is Read → Identify → Skeleton → Select → Compress → Paraphrase → Draft → Title → Count → Revise. Optional scratch fields capture topic, controlling idea, structure, essential/removable ideas, compression, paraphrase, reflection and a rewrite task. Hints require a written central idea. Full handbook comparisons require two different saved texts with a controlling-idea note; this is a disclosure gate, not an automated authorship or meaning assessment.

There are 39 editorially authored recognition drills adapted from the handbook, across all twelve requested skill areas. Answers are checked on the server; choice indices are not delivered before submission. These are instructional fixed checks, not an examination score. First responses remain immutable. The most recent wrong response must be followed by a correct check at least three days later to resolve its review signal. Immediate retries and intervening repeat errors cannot erase it. The profile explicitly reports its recognition-only basis; self-ratings, lesson openings and course-completion clicks never establish writing mastery. Stable/Mastered are withheld.

Chapter 2 and Appendix C explicitly distinguish the handbook's unverified marks assertion from verified official rules. The official FPSC document previously returned 503; the handbook's 20/15/5 statement is held pending independent verification. Roughly one-third is teaching guidance, not a universal official requirement. The /50 rubric is a self-check only. Source examples are preserved, and their models carry a reminder to check qualifications against the original rather than treating the model as the only valid answer.

## Native storage, access and history

`/account/precis` uses the existing ProfileGate, account shell and native PHP session. It is private, noindex/nofollow and ad-disabled. My Preparation exposes the Lab and attempt-specific links. The exact `/account/precis` path is added to the existing client/server membership return allowlist; arbitrary URLs and queries remain rejected. Existing free Précis resources and the generic saved-writing flow remain available. A version saved through the generic utility has no Lab title/scratch snapshot; it is shown explicitly as lacking that context and cannot count towards model disclosure. Future Précis evaluation must require a bound version context rather than trusting `kind=precis` alone.

All new course payloads and Lab mutations require server-verified active Pro. The overview delivers only the outline and owned history to inactive/expired members; premium lessons/questions are included only for active members. The private `_precis*` PHP helpers are protected by Apache rules and produce no standalone catalogue response. The existing test router denies direct helper access. No content is bundled into client JavaScript.

Additive SQL **016** reuses `preparation_attempts`, `writing_records`, immutable `writing_versions` and `learning_requests`. `precis_sources` permanently binds an owned Lab record to its original passage, attribution and explicit limit. `precis_version_context` stores the title, scratch notes, unscored/0–5 self-ratings and informational practice timer for each immutable version. `precis_progress` holds the owned day/chapter resume and additive completion record. `precis_responses` is an append-only server-checked response ledger; its response IDs are independent of user-supplied request IDs. Profile queries return first/latest responses and the most recent error for each question, with ownership and attempt filters.

Mutations validate fields, UUIDs, bounded text and scores; require a complete native profile, CSRF and expected-user identity; and use the shared account lock, request hash and idempotent receipt. Writing/progress saves enforce the current version; source/attempt changes on rewrite are rejected. Expiry rejects new premium actions while permitting owned history, profile, saved context, previously revealed models and exact replay of accepted requests. Full models are saved as an owned historical snapshot when revealed and are not overwritten on later reveals. A first reveal requires an exact match to the saved original, so a later source edition cannot supply a model for a different passage. No deletion, destructive migration, data reset or independent identity/database system is introduced.

Browser draft keys separate account, preparation attempt, source, record and immutable version. A pending save retains its exact submitted body and identity, disables editing until recovery, and replays safely after a lost response/reload. Known validation/conflict failures unlock the draft for correction. If browser storage fails, the interface reports it and retains in-memory work and retry identity while the page remains open. Course position saves include day and chapter; optimistic conflicts require refresh. Repeating completion after all 30 days are complete retains thirty unique days and remains saveable. Timers retain a wall-clock deadline through reload, never discard work at zero, and are explicitly a self-chosen practice aid rather than official timing.

## Honest comparison and next increment

History preserves every version and its actual title. History timestamps use explicit UTC ISO strings before display in Asia/Karachi, including when the browser itself is in Pakistan; numeric API fields are normalized. Comparison shows earlier/current wording, measured word counts, retained-length percentages and title changes, then asks the student to check fidelity. It **does not claim semantic improvement from a shorter draft**. Word counts use the established PHP/Unicode learning convention, excluding the title and treating internal hyphens/apostrophes as one word. An over-limit draft can be saved with an explicit warning for revision.

Full evaluation, free-text central-idea assessment, personalized title feedback, source-aware rewrite diagnosis and evidence-linked writing findings are **not open or implemented by this increment**. No dummy evaluation button is shown. The status is visible. The next increment must bind original passage + immutable student text + version title + rubric + useful weakness context to the shared guarded operation lifecycle, with the existing **two/day Asia/Karachi Précis allowance**. It must not reuse the generic paragraph prompt. Relevant genuine grammar findings can then feed the shared Writing Error Profile and exact Grammar lessons. Provider credentials, account capability, policy notice and launch approval remain outstanding; no real provider requests were made here.
